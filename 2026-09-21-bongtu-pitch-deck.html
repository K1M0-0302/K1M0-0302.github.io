봉투 3분 피치 — 다크 테크 템플릿을 버리고 서류 뭉치가 되기까지

  • HTML 슬라이드
  • Python
  • 프레젠테이션 디자인
  • 원샷 파이프라인

「봉투 — 뜯기 전까지는 아무도 모른다」는 국내 여행 서비스다. 예산과 취향만 고르면 목적지를 봉인한 티켓이 오고, 개봉하면 미션이 붙은 일정이 나오고, 비 예보를 켜면 일정이 다시 짜인다. 이 서비스는 IDEA.md 한 장에서 시작해 PRD와 TASKS.json을 거쳐, 메인 세션 하나가 서브에이전트 4개를 돌려 화면 4개를 나눠 만드는 "원샷 파이프라인"으로 만들어졌다.

이 글은 그 서비스를 3분 안에 보여주는 발표 덱을 만든 기록이다. 9월 21일 하루 동안 세 번 갈아엎었다.

덱의 규칙부터 정했다

디자인보다 먼저 정한 게 있다. 발표 대본의 「발표 메모」를 덱의 규율로 그대로 옮겼다.

  • 슬라이드에 올리는 수치는 기획서 근거표에 있는 것만 쓴다. Time Out 141개, SAS 6,000명, Pack Up + Go 45,000명, 총액 40만 원 같은 값이다.
  • "한 번 실행으로 나왔다"는 쓰지 않는다. 데모 실행은 중간에 스크립트를 줄여 같은 실행 ID로 재개한 회차였다. 무중단으로 끝까지 도는 걸 확인하기 전에는 원샷이라고 단정하지 않기로 했다.
  • 수정 루프 횟수도 말하지 않는다. 기획서에는 최대 2회라고 적었는데 재개판은 1회였다.
  • 시연은 슬라이드가 대신하지 않는다. 8장에서 배포 URL로 넘어가고, 막히면 녹화 영상으로 간다.

구조는 content.py(문장·수치 정본) → build.py(생성기) → index.html(생성물, 손으로 고치지 않음)로 나눴다. render.sh가 PDF, 장별 PNG, 컨택트시트를 한 번에 뽑는다.

1차 — 후보 3안과 다크 티켓

표지만 세 가지로 먼저 그렸다. A는 크라프트 봉투에 왁스 실, B는 목적지가 봉인된 티켓 스터브, C는 찢긴 틈으로 보이는 노을이다. 봉인된 티켓이라는 콘셉트가 서비스와 가장 잘 맞아서 B를 골랐다.

2차 — 검정 바탕을 버렸다

B안으로 13장(본편 10장 + 질의응답 백업 3장)을 만들었더니, 검은 바탕에 형광 라임 조합이 "AI가 뽑은 테크 템플릿"처럼 보인다는 지적을 받았다. 맞는 말이었다. 티켓 스터브 구조는 남기고 바탕을 뉴스프린트 종이로 바꿨다. 섬유결 두 겹, feTurbulence 인쇄 노이즈, 빛 방향 그라데이션을 얹었다. 포인트는 우표 코발트(#1F3A8A) 한 색만 남기고, 제목은 명조(Gowun Batang)로 바꿨다.

이 판을 검수할 때 대비 검사에서 49건이 걸렸다. 대부분 보조 텍스트 색(#7C7566, 3.6~4.0:1)이 문제였다. 프로젝터에서 안 보이는 문제라 넘기지 않고 색을 진하게 올렸다.

3차 — 「봉투 속 서류 뭉치」

종이판에도 "AI 슬롭이 많이 남아 있다"는 지적이 왔다. 진단은 네 가지였다. 카드 격자가 균일하다, 같은 틀이 반복된다, 문장이 슬로건 같다, 콘셉트 장치가 장식에 머문다. 네 가지 다 인정했다.

v2에서는 공용 틀(티켓 스터브, 상단 띠)을 전부 버렸다. 대신 슬라이드마다 다른 실물 서류 한 장을 책상 위에 올렸다. 국내 여행 실태는 체크된 설문지, 기존 서비스는 오려 둔 기사 스크랩, IDEA.md는 원고지, 파이프라인은 검인란이 있는 공정표, 비 예보는 기상통보 서식이다. 렌더러도 서류 종류마다 따로 뒀다(build.py의 r_* 함수 11개, 백업 3장은 문의 회신 서식 하나를 함께 쓴다).

문장은 "항목 — 값 — 단서" 형태의 서류체만 쓰기로 했다. "세 지점 모두에서 사람이 멈춘다" 같은 단정형 카피는 화면에서 빼고 발표자 노트(N 키)로 옮겼다. 설명은 발표자가 말로 하고, 화면은 서류만 보여준다.

발표 피드백으로 치수를 다시 잡았다

발표 뒤 피드백이 세 가지 왔다. 정렬과 여백이 장마다 다르다, 어떤 내용을 어떤 틀에 넣을지 기준이 없다, 글씨가 작아 뒷자리에서 안 읽힌다. 그래서 치수를 전면 개정했다.

  • 12열 그리드: 바깥 여백 200, 열 주기 128. 흔한 조합인 여백 120에 주기 140은 홀수 번째 시작선이 8의 배수가 안 돼서 버렸다.
  • 간격은 8px 배수만 쓴다.
  • 본문은 24px, 레이블은 20px이 하한이다. 개정 전에는 13~21px 선언이 52건이었다.

24px 하한 때문에 넘치는 곳은 글자를 줄이지 않고 내용을 깎았다. 공정 7단계는 5단계로 줄였다. CSS 검사 스크립트(check_layout.sh)로 돌리니 위반이 231건에서 0건이 됐다. 이 규칙은 내가 설치해 쓰는 ppt-design 스킬(팀원이 만든 것) 로컬 사본에 레이아웃 규칙 문서로 따로 정리해 두었고, 이 덱이 첫 적용 사례가 됐다.

자동 검사가 못 잡는 겹침은 13장을 한 장씩 눈으로 봐서 잡았다. 메모지가 스크랩과 겹친 것, 「개 봉」 도장이 라이브 띠를 파고든 것, 10장 제목이 소인과 겹친 것 등이다.

기술스택

  • Python(content.py + build.py) → 정적 HTML 슬라이드(1920×1080 고정 스테이지)
  • CSS(종이 질감, SVG feTurbulence 노이즈), 웹폰트 Gowun Batang · Pretendard · JetBrains Mono(2차 종이판은 Archivo도 사용)
  • Chrome headless PDF 인쇄, pdftoppm, ImageMagick 컨택트시트
  • 검수: scan_deck.sh(낱말 좌표로 경계 이탈 검사), check_layout.sh(크기·8px 배수), impeccable 4.1.0 detect

배운 점

  • "AI 티"의 정체는 대개 반복이었다. 같은 카드, 같은 틀, 같은 문장 꼴이 장마다 나오면 그렇게 보인다.
  • 콘셉트는 장식으로 붙이면 안 되고 레이아웃 자체가 돼야 한다. 봉투라면 서류가 나와야 했다.
  • 글씨가 넘치면 글씨를 줄이지 말고 내용을 깎는다. 뒷자리에서 안 읽히는 슬라이드는 없는 것과 같다.
  • 정직 규칙("한 번 실행으로 나왔다" 금지)은 디자인보다 먼저 정해야 덱 전체에 스며든다.
