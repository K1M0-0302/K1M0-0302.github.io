gamemaker-agent — 헤드리스 Godot로 게임을 만드는 에이전트

  • Godot
  • GDScript
  • Claude Code
  • Codex CLI
  • 헤드리스 테스트

8월 27일에 게임 제작을 맡는 폴더 에이전트를 만들었다. 엔진은 가리지 않기로 했지만, 지금 장비는 Godot 4.7.2 하나다. 게임 프로젝트 자체(project.godot, 씬, 스크립트, 에셋)가 산출물이라서 에이전트 폴더 밖 ~/Projects/03-personal/project-sky/game/에 둔다. 에이전트 폴더에는 엔진 호출 래퍼, 스킬, 서브에이전트, 설계·계획 문서만 있다. 에이전트 저장소는 9월 22일까지 70커밋이고, 게임 저장소는 따로 153커밋이다.

이 에이전트로 만든 게임은 「치킨나이트」다. 수탉이 주인공인 탑다운 액션 로그라이크다. 게임 내용보다 에이전트가 게임을 어떻게 만들고 확인했는지를 적는다.

8월 27일 — 출력이 사라지는 엔진

Windows용 Godot은 GUI 프로그램이라 셸이 종료를 기다리지 않았다. 출력도 사라졌다. 그래서 Godot은 직접 부르지 않고 래퍼(godot.ps1)로만 부르게 했다. 래퍼가 종료를 기다리고, 출력을 붙잡고, 종료 코드를 돌려준다. 실행 파일은 공식 릴리스에서 받아 SHA256을 대조해 두었다.

다음 날 확인한 것들이 이후 테스트의 바탕이 됐다.

  • --headless --script로 프로젝트 안 스크립트를 돌릴 수 있고, class_name 전역 클래스도 해석된다
  • 스크립트의 quit(n) 값이 프로세스 종료 코드로 그대로 나온다. 이걸로 테스트 러너를 만들 수 있다
  • 헤드리스에서도 물리가 돈다. 단, 노드를 붙인 직후 바로 move_and_slide()를 부르면 아직 물리 공간에 등록되지 않아 실패한다. await physics_frame을 한 번 거쳐야 한다

8월 28일 — 어서션 100개가 통과하는데 화면은 비어 있었다

8월 28일 하루에 계획 1~4를 썼다. 각 계획은 brainstorming이나 grilling으로 설계를 정하고, 계획서를 쓰고, 태스크마다 테스트를 먼저 쓰는 순서로 진행했다. 계획 1(토대·전투), 계획 2(던전: 시드 기반 방 8칸, 프리셋 5종, 문 통과, 미니맵), 계획 3(무기·유물·알 화폐·상점), 계획 4(보스·영구 사망·허브·영구 업그레이드)까지 가서 게임의 기본 루프가 닫혔다.

그 과정에서 어서션 100개가 전부 통과하는 동안 실제 게임 화면이 완전히 비어 있던 적이 있다. CollisionShape2D나 자리표시 텍스처는 충돌 판정은 되지만 실행 중에 아무것도 그리지 않는다. 헤드리스 테스트는 이걸 볼 수 없다.

그래서 렌더링 결과를 PNG로 뽑는 tools/screenshot.gd를 만들었다. 헤드리스를 빼고 실행하면 씬을 실제로 그린 뒤 저장하고, 색 분포를 함께 출력한다. 서로 다른 색이 1개면 빈 화면이다. 환경변수로 찍을 씬, 적 종류, 시드, 방을 비운 뒤 상태 등을 고를 수 있다. 에이전트는 이 PNG를 직접 열어 보고 확인한다.

같은 날 적은 Godot 함정이 여럿이다.

  • 테스트 스위트는 마지막에 done()을 불러야 한다. 런타임 에러로 중간에 잘린 스위트가 통과로 보고되는 걸 막는다
  • 물리 콜백(Area2D 시그널) 안에서 씬 트리를 바꾸지 않는다. 방 전환은 call_deferred로 프레임 끝에 미룬다
  • move_and_slide()는 정면 충돌에서 미끄러지지 않는다. 플레이어를 직선으로 쫓는 적은 장애물 바로 뒤에서 영원히 멈춘다. 이번 프레임에 실제로 나아갔는지 재고, 막혔으면 벽면을 따라 돌게 했다. 도는 방향은 한 장애물을 도는 동안 유지해야 한다. 매번 다시 고르면 좌우로 떨린다

8월 31일~9월 1일 — 그림은 Codex에게

도트 그래픽은 pixel-artist 서브에이전트가 맡는다. 실제로 그리는 일은 Codex CLI에 위임하고, 서브에이전트는 결과를 검수해 파일 경로와 실측한 피벗 값을 돌려준다.

첫 납품은 반려됐다. "멧돼지 산적"을 주문했는데 야생 멧돼지가 그려져 왔다. 반려 사유는 "멧돼지 병사지, 멧돼지가 아니다"였다. 이 게임 캐릭터는 전부 정면을 보고 두 발로 선 의인화 캐릭터인데, 그걸 의뢰서에 적지 않았다. 아트 한 사이클을 통째로 버렸다. 그 뒤 의뢰서에 "종족 이름이 아니라 직업 이름을 그린다"와 기준 스프라이트 파일을 넣었다. 6차 제작본에서 통과했다.

검수 방법도 정했다. 새 시트는 기존 시트와 나란히 이어 붙여서 본다. 따로 보면 형태가 따로 노는 게 안 보인다. 발 위치(피벗)는 최하단 두 줄의 가중 무게중심으로 잰다. 최하단 한 줄로 재면 -2.5, 프로젝트 방식으로 재면 -3.28로 달랐다.

9월 22일 — 리눅스로 옮기고, 테스트를 50배 빠르게

작업 머신이 Arch Linux로 바뀌었다. 시스템 패키지 Godot이 공식 빌드와 같은 커밋이었고, 콘솔 프로그램이라 출력 유실 문제도 없었다. 래퍼를 godot.sh로 바꿨다. 버전이 4.7.2가 아니면 실행 전에 멈춘다.

같은 날 계획 7(세 번째 구역 "말벌 둥지")을 진행하다 테스트 시간이 문제가 됐다. 전체 스위트가 실시간으로 약 100초 걸렸고, 워치독 한도는 240초였다. --fixed-fps 60을 붙이면 실시간 동기화가 꺼진다. 프레임은 최대 속도로 돌지만 물리와 타이머는 프레임당 1/60초 그대로 간다. 같은 스위트가 약 2초에 끝났고, 실시간 실행과 결과가 같은 것을 확인했다. 그날 마지막 기준선은 82 스위트, 2146 어서션이다.

플레이테스트 피드백도 같은 날 반영했다. 보스가 상자에 끼어 안 움직이는 문제, 대시 무적 시간(0.18초)이 대시 애니메이션(0.26초)보다 짧아 대시 중에 맞는 문제, 재입장하면 이미 산 물건이 다시 나오는 문제 등이다. 아이템 위에 서면 한글 말풍선으로 이름과 효과를 보여 주게 했다. 말풍선 문장은 데이터에 손으로 적지 않고 수치에서 만든다.

마지막으로 웹 익스포트를 검증했다. --export-release "Web"이 약 3초에 끝났다. 스레드 지원을 꺼서 별도 보안 헤더 없이 정적 호스팅에서 돌게 했다.

한 번은 스크린샷에 숨겨져 있어야 할 대시 게이지가 보였다. 확인해 보니 스크린샷 도구 창이 포커스를 가져가는 바람에, 사용자가 게임에 치던 키가 그 창에 들어가 대시가 실행된 것이었다. 프로브를 3번 다시 돌리니 전부 숨김이었다.

기술스택

  • Godot 4.7.2(GDScript), 헤드리스 테스트 러너(quit(n) 종료 코드, --fixed-fps 60)
  • 셸 래퍼: PowerShell(godot.ps1, Windows 시절) → Bash(godot.sh, Linux)
  • Claude Code 스킬(godot-headless)과 서브에이전트(pixel-artist), Codex CLI(도트 그래픽 제작)
  • 갈무리11 폰트(OFL, 한글 말풍선), Godot 웹 익스포트

배운 점

  • 테스트가 통과해도 화면이 비어 있을 수 있다. 눈으로 확인하는 도구를 따로 만들고, 그 도구가 빈 화면을 기계적으로 알려 주게 해야 했다.
  • 외주 그림은 당연해 보이는 전제부터 적어야 한다. "의인화"라는 말 하나를 빠뜨려서 한 사이클을 버렸다.
  • 시뮬레이션 시간을 고정하면 테스트가 빨라지면서 결과는 같다. 실시간과 결과가 같은지 한 번은 대조해야 믿을 수 있다.
  • 자동 스크린샷도 사람 환경 위에서 돈다. 포커스나 키 입력이 섞이면 결과가 오염된다.
