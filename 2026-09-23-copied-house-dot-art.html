2026. 9. 23. · 잘못 베낀 집

잘못 베낀 집 — 팩스로 온 방 그림과 소리를 맡다

  • JavaScript
  • Python
  • numpy
  • 도트
  • Web Audio
  • 텍스트 게임

「잘못 베낀 집」은 팀원이 설계하고 만든 한국어 텍스트 게임이다. 화면이 팩스 용지 한 장처럼 생겼고, 흑백의 서늘한 분위기 속에서 글을 읽어 나간다. 빌드 도구 없이 브라우저에서 바로 여는 정적 HTML·CSS·JavaScript다.

게임 설계와 글은 팀원의 몫이다. 나는 9월 23일에 합류해 24일까지 커밋 18개(인계 문서 2개 포함)를 남겼다. 이 글은 그 18개, 곧 그림과 소리와 글 다듬기만 다룬다. 내 커밋은 아직 팀원의 master에 합쳐지지 않은 작업 브랜치에 있다.

9월 23일 — 사진 대신 두 색 도트

원래 계획은 장면 그림을 이미지 생성 도구로 뽑아 1비트 디더로 전송하는 것이었다. 23일에 방향을 바꿨다. 「오브라딘호의 귀환」처럼 잉크색 #1b1b1b와 종이색 #f2f0ea 두 색만 쓰는 320×180 도트로 가기로 했다. 팩스 용지라는 화면과도 맞았다.

그리는 방식은 작은 3D 렌더러로 정했다. 상자, 원기둥, 평면으로 방을 짓는다. 그다음 문간 눈높이에서 손전등 하나로 비추고, 8×8 Bayer 디더를 건다. 마지막으로 깊이·법선·물체가 바뀌는 곳에 1px 윤곽선을 긋는다. 어두운 면 위의 윤곽선은 종이색으로 그어서 어둠 속에서도 실루엣이 읽히게 했다. numpy와 Pillow만 쓰는 Python 스크립트다.

처음에는 렌더러를 Codex CLI에 맡겼다. 결과가 좋지 않았다. 2D 손그림 판은 조명 방향이 거꾸로였다. 3D 렌더러 첫 판은 화면의 83%가 검정이었고, 다듬은 판은 전체가 같은 회색이 됐다. 그래서 역할을 나눴다. 조명은 Claude Code 세션에서 직접 다시 짰다. 그림자, 연속 명암에 S 곡선, 빛이 닿는 거리를 손봤다. 공용 렌더러(art-src/render.py)는 고정해 두고, 방마다 장면 파일(art-src/<방>.py)만 서브에이전트들이 나눠 썼다.

그날 렌더한 그림은 39장이다. 복도와 방 그림, 그리고 물건 클로즈업이다. 39장 모두 320×180이고, 정확히 두 색인지를 스크립트로 검사했다.

그림이 글보다 앞서 무언가를 말해 버리지 않게 하는 데도 신경을 썼다. 물건 배치에 어색한 빈자리가 생기면 고르게 다시 놓았다. 칫솔 그림자가 칫솔 하나가 더 있는 것처럼 보여서 조명 위치를 옮기기도 했다. 컵 벽을 뚫고 나온 칫솔은 입구에서 나오게 고쳤다. 단순한 3D 장면이라 물체가 겹치는 실수가 렌더 결과에서야 보였다.

판에 맞추기

게임 화면의 그림 판은 원래 사진을 런타임에 디더하는 구조였다. 도트 원고(폭 320px 이하)는 디더를 건너뛰고 그대로 싣게 했다. 처음에는 판을 꽉 덮고 위아래를 잘랐다. 그런데 1280×720 창에서 원고의 가운데 일부만 보였다. 그래서 판 안에 통째로 들어가는 배율로 바꿨다. 판 틀도 16:9로 장 폭을 다 쓰게 하고, 그만큼 글 칸과 선택지 높이를 줄였다. 1440×900 이하 창에서는 책상이 조금 스크롤된다. 판을 줄이는 대신 이 스크롤을 받아들이기로 결정했다.

9월 23~24일 — 음원 없이 만든 소리

배경음은 음원 파일 없이 Web Audio로 그 자리에서 만든다. 기성 곡을 쓰면 공개 페이지에서 무단 배포가 되기 때문이다. 구성은 이렇다.

  • 낮은 드론
  • 900Hz 부근으로 거른 잡음(방 울림)
  • 반음·삼온음·단9도처럼 불편한 간격에서 무작위로 고르는 긁는 음
  • 가끔 나는 FM 금속 울림

선율은 없고 매번 다르다. 분위기는 장면에 따라 네 가지로 바뀐다.

게임 오버 소리는 24일에 붙였다. 배경이 2.5초에 걸쳐 물속처럼 먹먹해진다. 그 사이 심장 박동이 점점 느려지다 멎고, 1kHz 삐- 신호음이 남는다. 박동과 신호음은 먹먹해지지 않게 따로 냈다. 귀 안에서 나는 소리라서다.

노트북 스피커로 들어 보니 배경음이 거의 안 들렸다. 재 보니 드론의 에너지 95%가 100Hz 아래였다. 작은 스피커는 그 대역을 내지 못한다. 220Hz 부근에 톱니파 둘과 삼온음을 몸통으로 올려 100Hz 아래 비중을 약 40%로 낮췄다. 오른쪽 위에는 소리 크기 밀대를 달았다.

게임 글 다듬기

24일에는 게임 글의 시제와 말투를 맞췄다. 지금 겪는 묘사는 현재형, 방금 한 행동의 결과는 과거형으로 통일했다. "귀에 와 닿는다" 같은 억지 몸 표현과 번역투도 풀었다. 예를 들어 "딸깍 소리가 귀에 와 닿는다"는 "딸깍 하는 소리가 난다"가 됐다. 게임 규칙에 걸린 낱말은 건드리지 않았다.

기술스택

  • 게임: 정적 HTML·CSS·JavaScript(빌드 도구 없음), Canvas, Web Audio API, node 내장 테스트 러너
  • 그림: Python 3, numpy, Pillow(직접 짠 광선 추적 렌더러)
  • 개발 보조: Claude Code(서브에이전트 병렬), Codex CLI(초기 렌더러 시도)

배운 점

  • 남이 만든 게임에 그림을 넣을 때는 그림이 글보다 먼저 말하지 않는지 따로 봐야 한다. 그림자 하나도 정보가 된다.
  • 결과를 좌우하는 공용 부분(조명, 렌더러)은 직접 잡고, 반복되는 장면 파일만 나눠 맡기는 편이 빨랐다.
  • 소리는 사람들이 실제로 들을 노트북·폰 스피커가 내는 대역을 기준으로 짜야 한다. 대역별 에너지를 재 보니 "안 들린다"의 원인이 바로 나왔다.
  • 정량 성과(플레이어 수 등)는 확인하지 못했다.
