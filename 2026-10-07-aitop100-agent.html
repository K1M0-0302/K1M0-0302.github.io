10월 7일 — 무엇을 만들지부터 정했다

카카오 AI TOP 100 일반 예선(10월 31일)을 앞두고 폴더 에이전트를 하나 더 세웠다. 처음엔 "대회에 낼 에이전트"를 만들까 했지만, 올해 제출 규격이 아직 공개되지 않아 그건 추측 위에 짓는 일이었다. 기출 원본 자료도 없어서 연습용 풀이기도 어려웠다. 그래서 정체를 대회 당일 참가자(나)가 문제를 푸는 데 쓰는 작업대로 좁혔다.

이 결정을 포함해 위치·산출물 폴더·스킬 구조·사람이 멈추는 자리·모델 배분·사전 설치·인터뷰 단계까지 여덟 가지를 질문 하나씩 짚어 합의하고, 기각한 대안과 이유를 설계 문서에 표로 남긴 뒤 착수했다.

기출 유형이 아니라 '손놀림'으로 쪼갰다

먼저 정리해 둔 기출 문제집(지난 일반 대회의 예선·본선 기출과 직전 회차인 CAMPUS 예선 5문제)을 다시 읽었다. 기출 유형마다 스킬을 하나씩 만들면 겹치는 동작이 많고, 처음 보는 유형이 나오면 쓸 스킬이 없다. 그래서 문제를 푸는 동작 단위로 일곱 개를 뽑았다.

  • extract-table — 그림·PDF·영상에 흩어진 자료를 표로 옮기고 몇 칸을 원본과 대조
  • rule-judge — 규칙 뭉치를 사례 한 건씩에 적용해 위반을 전부 모으고 우선순위로 고름
  • feedback-loop — 외부 API에 내고 점수를 읽어 스스로 고치는 루프를 백그라운드로
  • predict-validate — 예측하기 전에 검증셋부터 떼어 둠
  • hidden-find — 작은 글자·흰 글자·도형에 가려진 글자 찾기
  • image-to-code — 그림 속 코드를 복원해 실제로 컴파일·실행
  • interview-facts — 인터뷰 기록에서 사실·요구·기준·모순을 발언 위치와 함께 표로

기출 하나하나가 이 기법을 어떤 순서로 쓰는지는 따로 '플레이북'으로 적었다. 닮은 기출이 없을 때 펼칠 '조합 규칙'(자료가 그림이면 표로 옮기기부터, 규칙 목록 + 사례 여러 건이면 rule-judge 등)도 같이 넣었다.

사람이 멈추는 자리는 두 곳만

기출 수상 후기를 보면 여러 문제를 동시에 돌렸고, 본선은 짧은 시간에 문항이 많았다. 문제마다 사람을 여러 번 붙잡으면 병렬로 돌릴 수가 없다. 그래서 흐름을 이렇게 잡았다.

  1. 입구(aitop-problem-start) — 문제 폴더를 만들고 지문을 옮긴 뒤, 답 형식·기준일·우선순위·쓸 기법을 질문 한 번으로 못 박는다.
  2. 기법 스킬 1~3개 — 멈추지 않고 재계산·셀 대조·검증셋으로 스스로 검증하며 검증표·근거표를 채운다.
  3. 출구(aitop-submit-check) — 답 형식 검사 도구, 리뷰어 서브에이전트의 PASS/FAIL, 그리고 근거표를 보여 주는 질문 한 번.

답마다 파일명:줄, 표의 셀, 영상의 분:초 같은 근거 위치를 달지 않으면 출구에서 FAIL이 나도록 했다. "자료에 없으면 추측하지 말고 '확인 불가'로 쓴다"는 규칙도 하네스의 절대 규칙으로 박았다.

당일에 처음 돌려서 깨지지 않도록 — 합성 시험 자료

도구는 미리 전부 설치하고, 기법마다 합성 자료로 스모크 테스트를 만들었다. 기출 원본이 없으니 시험 자료는 생성 스크립트로 직접 만들었다.

hidden-find용 PDF는 겉으로는 평범한 문서지만, 흰색·2pt로 문장을 숨기거나 도형 아래·페이지 밖·주석에 줄을 숨긴 파일을 네 개 만들었다. 숨긴 문장은 expected.json에 정답으로 두고 도구가 찾아내는지 본다.

smoke_all.sh 하나로 일곱 개를 전부 돌리고, 하나라도 실패하면 종료코드 1을 내게 했다. 대회 전날과 당일 아침에 한 번씩 돌리는 것이 계획이다.

막힌 곳

영상 전사 도구에서 faster-whisper에 오디오 파일을 그대로 넘기면 깨졌다. 설치된 PyAV 버전과 faster-whisper의 오디오 디코딩이 맞지 않았다. ffmpeg로 wav를 뽑아 numpy 배열로 넘기는 방식으로 우회하고, 나중에 누가 "정리"한다고 되돌리지 않도록 규약 문서에 이유를 적어 두었다.

아직 비어 있는 곳도 분명하다. 올해 제출 규격과 인터뷰 화면 형식은 10월 23일 입장 이후에야 알 수 있어서, 형식 검사와 플레이북의 '올해' 절은 그때 고쳐야 한다. 실제 대회에서 쓴 결과는 아직 없다 — 정량 성과 미확인.

기술스택

  • Claude Code — 스킬 9개(입구·출구 + 기법 7), 리뷰어 서브에이전트, 산출물 위치 가드 훅
  • Python(uv) — pandas, scikit-learn, OpenCV, pytesseract(한국어 데이터), PyMuPDF, pdfplumber, faster-whisper, yt-dlp, openpyxl
  • 셸 도구 — tesseract, ffmpeg, gcc, qpdf, pdftotext · Gemini CLI는 영상·반박용 래퍼만 연결해 두었다(아직 로그인·사용 전)

배운 점

  • 규격이 공개되지 않은 대회는 "제출물"보다 "작업대"를 먼저 만드는 편이 추측을 덜 쌓는다.
  • 스킬을 문제 유형이 아니라 동작 단위로 나누니, 기출 대부분을 일곱 개 기법의 조합으로 다시 적을 수 있었다(몇몇은 눈으로 푸는 길이나 문서 작성 단계가 따로 붙는다).
  • 사람이 확인하는 자리를 줄이는 대신, 그 자리에서 볼 것(근거표)을 미리 정해 두는 쪽이 병렬 작업과 검증을 같이 챙기는 방법이었다.
