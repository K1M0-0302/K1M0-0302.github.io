어업 데이터·직거래 플랫폼 (fish-data-platform)

상황 (Situation)

소규모 어업인은 최대 6단계에 이르는 유통구조를 거치며 유통비용률이 늘고 생산자 수취율은 줄어드는 추세였다. 어업인이 직접 상품을 등록하고 소비자가 바로 주문할 수 있는 직거래 채널이 없어 이 문제가 방치되고 있었다.

과제 (Task)

소규모 어업인이 상품(어종·수량·가격)을 직접 등록하고(F-01), 소비자가 그 상품을 주문·결제할 수 있는(F-02) 직거래 플랫폼의 MVP를 만드는 것이 과제였다. 결제·배송은 자체 구축하지 않고 외부 PG· 택배사 연동으로 해결하며, 디지털 사용에 익숙하지 않은 고령 어업인도 쓸 수 있도록 UI를 단순화하는 것이 제약이었다.

행동 (Action)

  • Next.js(App Router) + Supabase(Postgres·Auth·RLS)로 아키텍처를 잡고, 인증·데이터는 Supabase에 맡기고 UI·서버 액션은 Next.js가 담당하도록 역할을 나눴다.
  • 회원가입·로그인과 역할(어업인/소비자)에 따라 다른 화면을 보여주는 헤더를 구현했다.
  • 어업인이 상품(어종·수량·가격)을 등록하는 기능(F-01)과, 소비자가 공개 상품 목록·상세를 보고 주문을 생성하는 기능(F-02의 주문 생성 부분)을 구현했다.
  • 주문 총액은 클라이언트를 신뢰하지 않고 서버 액션이 DB의 가격으로 항상 다시 계산하도록 설계· 구현했다 — 클라이언트가 보낸 금액을 그대로 쓰지 않는 원칙을 지켰다.
  • zod로 입력 검증 스키마를 만들고, order.ts(주문 총액 계산)와 validation.ts(입력 검증)는 Vitest 단위 테스트를 함께 갖춰 구현했다.
  • DB 스키마·RLS는 supabase/migrations/0001_init.sql 하나로 관리했고, 세션 갱신은 미들웨어로 처리했다.

결과 (Result)

커밋 8개로 스캐폴딩부터 상품 등록(F-01), 상품 목록·상세, 서버 사이드 금액 계산이 들어간 주문 생성까지 구현했다. 결제(토스페이먼츠) 연동, 주문 내역·배송(운송장 입력) 화면, 실제 배포는 계획 단계에만 있고 아직 구현하지 않았다 — 즉 F-02(주문·결제)는 주문 생성까지 완료됐고 결제 승인 단계는 남아 있다.

기술스택

Next.js 16(App Router) · React 19 · TypeScript · Tailwind CSS 4 · Supabase(@supabase/ssr, @supabase/supabase-js, Postgres + Auth + RLS) · zod · Vitest · ESLint

정량 성과

정량 성과 미확인. (배포·실사용 전 개발 단계의 프로젝트로, 사용자 수·거래액 등 운영 지표가 없다. PRD에 있는 "입점 어업인 10명·월 거래액 500만원"은 3개월 후 목표 수치이며 달성치가 아니므로 여기에 쓰지 않았다.)

회고·배운점

Supabase 연동과 서버 사이드 금액 검증을 구현하면서 배운 게 많았다.
