기획 문서 에이전트 (pm-agent)

개요

프로젝트 하나를 받아 사용자를 인터뷰하고 리서치 보고서·코드를 읽어, 표준 8절 PRD(요구사항 문서)와 표지+15절 PROPOSAL(기획서)을 쓰는 폴더형 에이전트. 모든 사실 주장에 출처 표기를 강제하고, 결함을 심은 문서로 검증한 리뷰어 서브에이전트의 PASS가 완료 조건이다.

배경과 문제의식

기획 문서는 "그럴듯하게 쓰는 것"이 가장 쉽고 가장 위험하다. 근거 없는 시장 수치, 인터뷰에서 나오지 않은 요구사항이 문서에 스며든다. 이 에이전트는 출처 없는 문장을 리뷰어가 기계적으로 잡아내는 구조로 그 문제를 막는다. 기획서 템플릿 자체도 PMBOK 8판·ISO 21502·Green Book 2026을 종합한 리서치 보고서를 근거로 설계됐다.

구조와 개념

  • 두 문서의 공존: 기획서(PROPOSAL) = 왜 하는가/승인, PRD = 무엇을 만드는가/요구사항. 같은 pm\ 폴더에 나란히 산다. 기획서에는 BAU(현행 유지) 대안, 운영비, 위험별 책임자가 강제 요소다.
  • 인터뷰 규율: AskUserQuestion으로 한 번에 질문 하나, 선택지 제공. 입력 자료에서 답이 나오는 항목은 건너뛰고 확인 한 번으로 대체한다.
  • 출처 강제: 웹 출처는 원어 제목·URL·접근일, 리서치 보고서는 경로, 인터뷰는 (사용자 인터뷰) 문단 단위 표기. 리뷰어(pm-reviewer·proposal-reviewer)는 고치지 않고 문제 목록만 반환하며, 루프는 최대 2회 — 그 뒤 잔여 항목은 사용자에게 보여주고 멈춘다.
  • 자동 체인: PROPOSAL.md 저장이 감지되면 PostToolUse hook이 Orca CLI로 같은 세션에 /pm-prd 후속 프롬프트를 자동 큐잉한다 — 기획서가 끝나면 PRD 작성으로 자연스럽게 이어진다.
  • 산문 다듬기의 외부 위임: 언어적으로 어려운 절은 codex exec 비대화 호출로 위임할 수 있다. 출처 표기·헤딩은 불변 제약이고, 실패하면 건너뛰고 직접 다듬는다.

개발 과정

  • 2026-08-22 grilling으로 PRD 쪽 설계를 확정하고, 2026-08-25 brainstorming으로 기획서 쪽을 확정했다(리서치 보고서가 템플릿 설계의 근거 문서로 남아 있다).
  • 리뷰어를 리뷰어답게 검증했다: 결함 9개를 일부러 심은 PRD를 만들어 pm-reviewer에 넣었더니 심은 결함 전부에 더해 미사용 출처 2건을 추가로 적발했다(FAIL 13건). 기획서 리뷰어도 결함 10개를 심어 전부 적발됨을 확인했다. 검증 장치는 이렇게 실패 사례로 검증해야 신뢰할 수 있다.
  • 실운행: /pm-prd 1회(2026-08-22), /pm-proposal 1회(2026-08-26) — 둘 다 임시 프로젝트 대상, 리뷰 1회차 PASS.
  • Codex 위임에서 인코딩 함정을 또 만났다(2026-08-26): stdin 파이프로 텍스트를 넘기면 PowerShell 5.1이 CP949로 넘겨 mojibake가 되고, Codex가 깨진 내용을 추측하다 명사를 바꿔 의미를 훼손했다(실측). 파일 경로 방식으로만 위임하도록 확정했다.
  • proposal→prd 자동 체인은 일회용 Orca 터미널을 만들어 실제 전송→수신 확인→폐기까지 파이프 테스트로 검증했다.

현재 상태

  • 검증됨: 가드 자가 테스트 15검사 통과, 템플릿 자리 채우기 검사(PRD 30개·기획서 전체 자리표시자), 리뷰어 2종의 심은 결함 적발, 실운행 각 1회, Codex 위임 스모크 테스트.
  • 미검증: 산문 다듬기 패스를 포함한 전체 워크플로 무인 검증(인터뷰가 무인 불가), 세션 중 추가한 hook의 실차단 재확인(형제 research-agent에서 원인이 인코딩으로 규명된 뒤 새 세션 확인 대기), proposal→prd 자동 체인의 실제 세션 내 발동(파이프 테스트만 통과).

기술스택·도구

Claude Code(스킬 2종·리뷰어 서브에이전트 2종·PreToolUse/PostToolUse hook) · PowerShell 5.1 · Node 22(proposal→prd 체인 스크립트) · Orca CLI(세션 간 프롬프트 큐잉) · Codex CLI(산문 다듬기 위임)

배운 점

  • 리뷰어는 정상 문서 통과만으로는 검증이 안 된다 — 결함을 심은 문서를 전부 잡아내는지 봐야 한다.
  • 도구 간 텍스트 전달에서 인코딩은 반복적으로 사고 지점이다. stdin 파이프 대신 파일 경로 전달이 Windows 한글 환경의 안전한 기본값이다.
