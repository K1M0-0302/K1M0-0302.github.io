스킬 해설 작업대 (skills-manager)

개요

설치된 Claude Code 지시문(스킬·서브에이전트·rules·CLAUDE.md)이 실제로 무엇을 하는지 해부해 해설 리포트를 내는 폴더형 에이전트. 설명만 하고 고치지 않는다 — 개정은 별도 도구(skill-tdd)의 몫이라는 역할 분리가 핵심이다.

배경과 문제의식

스킬과 지시문이 수십 개 쌓이면 "이게 정확히 뭘 하는 물건인지"를 아무도 모르게 된다. 더 나쁜 것은 적힌 지시와 실제 집행이 어긋나는 경우다 — 지시문은 텍스트일 뿐이고, 로드되는지·따라지는지는 별개 문제다. 이 에이전트는 「선언 × 집행」 대조를 체계화한다.

구조와 개념

  • 정본 경계가 첫 번째 규칙: 동작하는 실물은 ~/.claude/ 아래에 있고 거기가 정본이다. 스킬 파일을 작업대로 복사하지 않는다(사본은 즉시 표류한다). 개정은 제자리에서.
  • 출처 5종 판정: 실디렉터리 / 심링크(실물은 ~/.agents/ — 다른 AI 도구와 공유) / 플러그인 캐시(개정 불가 — 업데이트가 덮는다) / 빌트인(디스크에 없음) / repo 종속. 어느 칸인지 판정하지 않고 고치면 플러그인 캐시를 고쳐놓고 다음 업데이트에 조용히 잃는다.
  • 작업대와 원장의 분리: 여기는 해부하는 작업대, 개정 기록은 별도 원장 저장소에만 쌓인다. 두 곳에 적으면 갈라진다.
  • 관측 오염 방지: 이 에이전트의 가장 흥미로운 설계 결정 — 집행 관측을 Task 서브에이전트로 돌리지 않는다. 에이전트의 CLAUDE.md가 서브에이전트에 자동 주입되므로(실측), 프로브가 자기 답이 무엇에 쓰이는지 알고 답하게 되고, 지시를 잘 따르는 척하는 쪽으로 기울어 재려던 신호가 사라진다. 대신 CLAUDE.md 조상이 없는 임시 폴더에서 claude -p 셸을 돌린다. 같은 이유로 이 repo에는 의도적으로 .claude/agents/가 없다.

개발 과정

  • 2026-08-05 실측에서 플러그인 생태계의 함정을 적립했다: 플러그인 캐시의 .in_use 마커는 활성 표시가 아니었다(두 버전에 동시에 붙어 있었다). 활성 버전의 유일한 근거는 installed_plugins.json의 installPath 하나이며, 캐시에는 SKILL.md가 194개 쌓여 같은 스킬이 버전별로 중복된다.
  • 진단 기준은 외부 리서치를 그대로 믿지 않고 로컬 원본과 대조해 통과분만 채택했다 — 어긋난 6건은 폐기 이유와 함께 별도 섹션에 남겼다.
  • 이 작업대에서 이웃 에이전트(pm-agent)의 해설 리포트와 개정 작업을 실제로 수행했다 — 다른 에이전트를 해부·개선하는 메타 도구로 작동한 실적이다.

현재 상태

  • 해설 절차(skill-xray)와 판정 기준은 갖춰졌고 실운행 실적이 있다. 스키마는 아직 스킬 기준이라 서브에이전트·rules 해설은 실제로 돌려보며 갈라지는 부분을 적립하는 중. 빌드도 테스트도 없다 — 검증은 실제로 돌려 리포트를 읽는 것이다.

기술스택·도구

Claude Code(스킬, claude -p 헤드리스 프로브) · 플러그인 시스템 내부 구조(installed_plugins.json, 캐시 레이아웃) · 심링크 기반 다중 도구 공유(~/.agents/)

배운 점

  • 관측 도구가 관측 대상을 오염시킬 수 있다 — 지시문이 자동 주입되는 환경에서는 "깨끗한 방"을 따로 만들어야 진짜 집행을 잰다.
  • 편리한 길(서브에이전트 등록)을 일부러 막아두는 것도 설계다. 만들어두면 다음 세션이 그 쉬운 길로 간다.
